## Promotion plan if the protocol becomes satisfiable

An explicitly assigned lane and a refreshed, complete registry are prerequisites. The top candidate would be checked for pre-placement rank correlation and dot-overlap first; **stop** on any threshold breach. Reuse the pinned shared evaluator/writer and cached features rather than introducing a private implementation. Hide whole buffered fault segments, compute any catalogue feature from visible faults in each fold, mask visible pixels exactly, then run per-feature leakage canaries and a paired same-fold comparison against the frozen current best. A bootstrap confidence interval is conditional on that sampling design; it is not an estimate of the private leaderboard. The protocol allows at most three experiments or two hours, followed by a separate selector; no weekly slot is used during research.

The shared GEMSDOE32 `submission_writer.py` currently converts all positive continuous values to a Boolean mask; this is incompatible with preserving probabilistic outputs. Do not silently use it for soft predictions. Fix the canonical template, not a private fork, and add a round-trip test before a future continuous lane. Binary-only use is a separate question.
