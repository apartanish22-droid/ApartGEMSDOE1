# Agent instructions for ApartGEMSDOE1

At the start of every session, read the entire root `README.md`. Treat its standing project brief, parallel-run protocol, evidence rules, and fail-closed submission status as mandatory.

Before any new experiment:

1. Inspect the current branch, worktree, current release decision, and provenance records.
2. Confirm the prompt supplies exactly one method-lane paragraph. If it is missing, do not infer one and do not generate or promote a TIFF.
3. Reuse the shared template's cached feature stack, `evaluate_holdout.py`, and `submission_writer.py`. Do not copy/fork these tools into this repository. Fix shared defects at their shared source.
4. Preregister three to five genuinely distinct hypotheses before implementation. Identify layers, signature, off-catalogue rationale, prior-method distinction, mimics, data provenance, and cost.
5. Test each feature alone for leakage. Recompute catalogue-derived steps from only visible faults inside every whole-segment buffered holdout fold; mask visible faults pixel-exactly.
6. Enforce the declared experiment/time budget, compare candidate and incumbent with the same evaluator and withheld positives, and label every score only as HOLDOUT-DTI (version, withheld positives, 95% CI) or ORGANIZER-CONFIRMED (receipt).
7. Check candidate surfaces against the registry before placement and final dots after placement. Stop on the specified correlation/overlap thresholds.
8. Emit a new TIFF only if all scientific, uniqueness, and saved-byte validator gates pass. Keep the portal slot selector separate. A valid file format alone is not approval.
9. Do not add previous submissions or competition datasets to Git unless specifically required and permitted. Prior TIFs may be used only for read-only audit/education and should not be copied as a new candidate.
10. End experiment reports with the single JSON run card defined in the README; negative results are deliverables.
