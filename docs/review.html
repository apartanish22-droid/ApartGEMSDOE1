Pass 1 — inventory and source review

  • The starting checkout contained exactly one tracked file, README.md, with only a title. There was no application, test suite, workflow, data, `.tif`, feature cache, registry, holdout evaluator, or submission writer.
  • The official reference-solution repository was inspected on GitHub. Its README asks users to download the competition rasters into data/, and its notebook presents a U-Net patch-training baseline. Its own README is not the missing shared hide-and-recover toolset for this checkout.
  • A related, owner-maintained GEMSDOE32 repository was reviewed read-only. It contains a focus-site manifest, historical TIFs, and a current negative release record; it is not an official organizer source and its files were not copied into this repository.

Pass 2 — independent checks and irregularities

  • Historical file hash integrity: one allfinite companion TIF for each selected site was fetched through the pinned owner-registry manifest into a temporary directory. The SHA-256 of every fetched file matched its manifest entry. The nine companions were single-band float32, the same stored CRS/shape/transform, finite, and binary in [0,1]. For the five selected rows whose prompt-listed version used a -nan suffix, the positive-pixel mask was also checked identical against that pinned NaN variant; those variants contain NaNs outside the footprint. This may explain a range error, but cannot prove the cause without the exact failed upload bytes. This is a standalone file audit, not a comparison against the missing official sample-submission raster and not a claim that these are the exact artifacts previously uploaded by the user.
  • Final-dot uniqueness: a pairwise read-only comparison shows every selected historical mask violates at least one required gate: absolute binary-grid Spearman correlation above 0.90 or more than 70% of the source dots within 3 px of another selected map. GEMSDOE25 and GEMSDOE30 are exactly equal as positive-pixel masks even though their byte hashes differ. The GEMSDOE32 dots are a strict subset of the selected GEMSDOE25 and GEMSDOE31 maps; the selected GEMSDOE36 map contains all GEMSDOE32 dots and has additional positives. See the complete pairwise data in focus-site-audit.json.
  • No pre-placement surface check: the archive exposed the final binary outputs used above, not all underlying unthresholded prediction surfaces. The pre-placement surface-correlation gate therefore remains unavailable; a final-dot failure is sufficient to reject the audited historical candidates.
  • Score provenance: no submission-page receipt binding the quoted historical score to an exact hash was found in this checkout. The related owner repository explicitly distinguishes owner-reported claims from organizer-confirmed receipts. No historical score is used as a valid estimate here.
  • Leaderboard freshness: the prompt contains different leader values and the related archive has its own timestamped snapshots. This sandbox did not fetch the official DrivenData leaderboard, so no value is labeled current.
  • Lane omission: the parallel-run protocol asks for a single method paragraph, but none is provided in the current prompt or this checkout. The stop condition is followed; no lane was inferred.
  • Metric-algebra inconsistency in the related archive: the H48 results note derives an isolated-credit bar of alpha × DTI / (1 - alpha × DTI), while the same archive's current metric module says that older form is not the isolated-pixel threshold and implements alpha × DTI, with a regression test. Treat the H48 prose derivation as internally inconsistent until reconciled with the organizer's exact metric specification. No inclusion-threshold calculation from that prose is used here.
  • Holdout vs leaderboard: the related H48 record compares one HOLDOUT-DTI run with another HOLDOUT-DTI baseline. That does not show a higher organizer score. Its release record is negative due to a final uniqueness/release gate; this repository does not link or copy its TIFF.
  • Reported portal range error: the nine archived TIFs audited here have finite stored binary values in [0,1]. Without the exact failed file's SHA-256, this cannot identify the cause of the reported portal error or prove that a different downloaded artifact was safe.

What the H33/B2 result suggests (and what it does not)

The raster relationships support a lineage hypothesis: the H33/B2 mask is a sparser descendant of a shared, H19-5-derived pattern. Under the asymmetric distance-weighted Tversky objective specified in the task, removing predictions with little marginal credit can reduce the false-positive term while retaining nearby coverage. That is a plausible explanation for why a sparse mask could rank better than denser relatives.

It is not a verified causal explanation of an organizer score: there is no exact-byte submission receipt, no independent reconstruction of the hidden labels, and no compliant holdout of the archived candidate in this checkout. It does not establish that the surviving dots correspond to undiscovered geothermal faults. The only defensible test of a new method is the prescribed spatially blocked hide-and-recover evaluation, followed by a separately authorized live submission.
