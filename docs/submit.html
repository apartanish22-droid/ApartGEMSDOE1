Pre-submission checklist for a future approved candidate

  1. Confirm the green decision first. On the executive-summary page, the exact candidate file must be marked OK TO DOWNLOAD AND SUBMIT and must link to a run card with verdict promote. “Format valid,” “research download,” a good holdout alone, or a projected score is not approval.
  2. Download the exact file once and preserve its bytes. Do not edit, reproject, resample, rename internally, or replace nodata values. Verify the SHA-256 against the run card after download.
  3. Check the saved GeoTIFF automatically. Require one band; exact sample-submission CRS, width, height, and transform; finite prediction values in [0,1] over the stored array; zero NaN inside the valid footprint; supported dtype; and a post-write hash. This strict all-array range check is intended to prevent the reported “Predicted values must be in range [0, 1]” error.
  4. Check scientific and uniqueness gates. Confirm the same versioned hide-and-recover evaluator, withheld-positive count, 95% CI, feature-alone canaries, surface correlation before placement, final-dot overlap after placement, and a passing separate selector decision. The current historical entries do not pass the uniqueness rule.
  5. Open the official competition page and sign in. Use the DrivenData DOE GEMS competition page, then choose the competition's submission action. The page wording supplied in the project request says the upload accepts a single-band GeoTIFF or a ZIP containing exactly one GeoTIFF; verify the current portal instructions before each upload.
  6. Select the approved artifact. Choose the exact .tif file, or its approved ZIP if supplied. Do not upload the explanatory HTML, JSON, a companion research raster, or two TIFFs in one ZIP.
  7. Enter a short distinguishing note. Use the exact run-card note (maximum 140 characters). It should identify the hypothesis/experiment and hash suffix; never put a projected leaderboard score in the note.
  8. Submit once and save the portal receipt. The organizer receipt is the only basis for labeling that leaderboard score ORGANIZER-CONFIRMED. Record the receipt, submission identifier, exact file hash, date, and result. Do not treat an owner-maintained webpage or a local holdout as an organizer receipt.
